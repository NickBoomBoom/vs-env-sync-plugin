# 多设备、多分支 Env 同步可靠性设计

## 目标与背景

用户通过多台设备同步同一个 Git 项目在不同分支上的 env 文件。当前实现把本地文件集合当作远端完整镜像，会将其他设备刚上传的文件误判为本地删除；全局审查还发现提交范围、失败恢复、跨窗口并发、身份碰撞和路径安全等问题。

本次目标是将插件完善为可长期使用的多设备同步工具，同时保留现有“专用配置仓库 + 项目分支目录”的使用方式。

## 范围

### 必须实现

- 使用每台设备独立保存的同步基线进行三方比较，杜绝远端新增文件被误删。
- 本地和远端同时修改、同时删除或删改冲突时，不静默覆盖数据。
- 配置仓库提交严格限定到当前项目分支目录，保留其他已暂存和未暂存改动。
- commit、push 或旧数据继承中断后，后续打开工作区和文件事件可以恢复，不要求文件再次变化。
- 多 VS Code 窗口共享配置仓库时使用跨进程互斥，不能并发修改同一工作树。
- 项目身份、分支目录和文件路径必须防碰撞、防路径越界，并兼容已有数据。
- 切换配置仓库分支不得重置已有本地分支或丢失未推送提交。
- 扩展自身造成的 watcher 事件与真实用户编辑必须可区分。
- worktree 分支切换、配置刷新重入和 detached HEAD 不得使用过期上下文。
- 大型项目扫描不得栈溢出，并避免遍历明确忽略的依赖和构建目录。
- 用户可见日志和错误中的仓库凭据必须脱敏。
- README、中文 README 和 CHANGELOG 与实现保持一致。

### 非目标

- 不实现 env 内容逐行合并；冲突仍以整个文件为单位由用户选择。
- 不加密 env 内容；配置仓库仍必须是用户可信任的私有仓库。
- 不自动创建远端配置仓库。
- 不增加持续远端轮询服务；同步仍由打开工作区、本地事件、配置变化和失败后的后续同步触发。
- 不保证多台设备同时 push 永远不需要重试，但必须能安全恢复。

## 方案比较

### 方案 1：本地同步基线 + 三方比较（已选择）

每台设备记录每个项目分支上次同步成功时的文件哈希。每次同步比较基线、本地和远端，只有本地相对基线发生变化时才向远端写入，只有远端相对基线发生变化时才向本地写入。

优点是不改变用户使用方式，能直接解决远端误删和冲突跳过失效，并可逐步迁移现有数据。代价是需要可靠地持久化基线，并定义首次同步和失败恢复规则。

### 方案 2：每台设备独立 Git 分支后合并

利用 Git 分支和合并历史协调设备变更。能复用 Git 三方合并，但会产生设备分支、更多合并状态和更复杂的冲突界面，现有同步流程需要重写，因此不采用。

## 三方同步模型

### 基线内容

基线按“配置仓库 URL + 配置仓库分支 + 本地项目真实路径 + 完整项目身份 + 项目分支”隔离，保存在扩展全局存储的 `sync-state/` 中。文件名使用上下文 SHA-256，内容采用带版本号的 JSON，记录每个已同步相对路径的 SHA-256。切换 `configRepoBranch` 必须使用另一份基线，不能把新配置分支的文件缺失误判为旧配置分支上的远端删除。

基线只在对应同步事务成功后原子更新：先写临时文件，再 rename。冲突跳过、commit/push 失败或同步中断时不把该路径标记为已同步。同步删除成功后移除基线条目。

### 状态判断

对每个本地与远端匹配路径的并集，计算：

- `base`：上次同步成功的内容哈希或不存在。
- `local`：当前本地内容哈希或不存在。
- `remote`：当前远端内容哈希或不存在。
- `localChanged`：本地状态与基线不同。
- `remoteChanged`：远端状态与基线不同。

规则如下：

| 本地变化 | 远端变化 | 行为 |
| --- | --- | --- |
| 无 | 无 | 不处理 |
| 有 | 无 | 应用本地新增、修改或删除到远端 |
| 无 | 有 | 应用远端新增、修改或删除到本地 |
| 有 | 有，且当前内容相同 | 视为已经收敛，只更新基线 |
| 有 | 有，且当前内容不同 | 提示拉取远端、上传本地或跳过 |

无基线的首次同步采用保守规则：

- 仅远端存在：拉取；在后台推送同步中也必须拉取，不能删除远端。
- 仅本地存在：打开工作区时保留现有上传/跳过提示；由本地文件事件触发时上传。
- 两边都存在且内容相同：记录基线。
- 两边都存在但内容不同：提示冲突选择。
- 两边都不存在：不处理。

用户选择跳过时保留该路径旧基线，因此后续同步仍会识别冲突，不会被其他文件的保存事件静默覆盖。

### 同步结果与事件

打开同步和本地变更同步共用同一三方决策函数。后台同步可能拉取远端新增、修改或删除，因此结果必须同时包含 pulled、pushed、deleted 和 skipped 路径。

所有扩展写入或删除本地文件的路径都交给 watcher 抑制机制，并返回给用户可见摘要。

## 项目身份与存储兼容

### 完整项目身份

origin 解析必须保留完整项目组路径，而不是只保留最后两个路径段。host 统一小写，项目路径保留原始大小写并去掉 `.git` 后缀；`slug` 用于日志和提示时包含完整路径。

拒绝空段、`.`、`..`、NUL、控制字符、反斜杠及其他会导致路径解析歧义的段。无法安全解析的项目跳过并记录警告。

### 防碰撞目录

新的物理存储路径不再直接拼接原始 owner/repo/branch：

```text
projects/<safe-host>/<sha256(full-project-path)>/branches/<sha256(raw-branch-name)>/
```

项目目录和分支目录保存仅供诊断的元数据，文件扫描始终排除这些内部元数据。哈希输入使用明确版本化的 UTF-8 规范字符串，避免大小写、Unicode 归一化、多级 group 和分支大小写造成碰撞。

所有路径构造后使用 `path.resolve` 和 `path.relative` 验证仍位于配置仓库预期根目录；文件写入前同样验证目标位于当前分支目录内。

### 旧数据迁移

每个新分支目录使用纳入 Git 提交的初始化标记表示迁移已经完成。标记不存在时按以下顺序寻找匹配数据：

1. 当前 `projects/<host>/<owner>/<repo>/branches/<encodeURIComponent(branch)>/` 分支目录。
2. 更早已有的项目共享目录 `projects/<host>/<owner>/<repo>/`，排除 `branches/`。

迁移允许续传：只复制新分支目录中仍缺失的文件，全部复制完成后才写入初始化标记，再将标记和数据一起提交。即使没有旧数据，也写入空初始化标记，避免以后旧目录变化触发继承。复制中断时没有标记，下次继续复制其余文件；标记已写入但 commit/push 中断时，后续同步继续提交已有数据。初始化完成后不再读取旧目录，因此已同步删除的文件不会被旧数据复活。旧目录和旧文件始终保留。

## Git 事务与恢复

### 分支和刷新

- 已在目标分支时直接复用。
- 本地目标分支存在时直接 checkout，不再用 `checkout -B` 重置。
- 仅本地分支不存在时从 `origin/<branch>` 创建跟踪分支。
- 已 fetch 后执行 `git rebase --autostash origin/<branch>`，不使用依赖共享 `FETCH_HEAD` 的 `git pull`。
- rebase 或 autostash 发生真实内容冲突时保留 Git 状态并给出明确手动处理错误，不强行 reset。

### 提交范围

当前分支目录先 `git add -A -- <branch-path>`，再使用带相同 pathspec 的 `git commit -m <message> -- <branch-path>`。其他项目的 staged/unstaged 文件必须保持原状态，不进入本次提交。

每次同步结束都检查当前分支目录是否有未提交变化，即使本轮没有本地文件差异也执行检查，以恢复中断的继承或写入。

### push 失败恢复

refresh 后比较本地 HEAD 与远端跟踪分支；存在 ahead 提交时，即使本轮没有文件变化也执行 push。远端分支尚不存在但本地已有待发布提交时，也允许建立上游并推送。

commit 与 push 分开处理结果。push 被拒绝时重新 fetch/rebase 后进行有限次数重试；最终失败则保留本地提交，由下一次打开或文件事件继续恢复。只有远端接受相关提交后才推进对应基线。

## 跨窗口互斥

同一台机器的多个扩展宿主仍使用相同配置仓库 clone，因此必须为每个配置仓库增加跨进程锁。

锁位于全局存储的 `locks/<config-repo-hash>.lock/`，通过原子 `mkdir` 获取。锁内记录 PID、随机所有者 ID 和租约时间，持有期间定期更新租约。等待方通过 PID 存活检查判断持有者状态：进程仍存活时，即使系统休眠或长 Git 操作导致租约暂停，也不得接管；只有确认持有 PID 已退出时才清理死锁。租约时间用于诊断，不能单独成为接管依据。释放时验证所有者 ID，finally 中必定执行。

锁覆盖完整事务：ensureReady、fetch/rebase、三方同步、commit、push 和基线更新。进程内 SerialQueue 继续保留，跨进程锁补足多窗口保护。等待锁不得跳过同步，释放后等待者重新读取最新远端和文件状态。

## watcher、worktree 与会话生命周期

### 精确事件抑制

删除当前固定 10 秒抑制。扩展写入本地文件前记录路径及预期内容哈希，删除则记录预期不存在；watcher 收到事件后读取实际状态，仅在完全匹配时消费一次抑制记录。内容不同的真实用户编辑必须立即进入同步。

### 分支上下文

项目上下文缓存不得长期固定分支。每次打开同步和本地事件同步前重新读取当前 symbolic-ref；detached HEAD 立即跳过。

除现有 `.git` watcher 外，通过 `git rev-parse --git-path HEAD` 找到 worktree 的真实 HEAD 并监听，分支变化时使上下文失效。嵌套项目继续按最长项目路径匹配。

### 配置和会话刷新

WorkspaceCoordinator 的 refreshSessions 必须串行或合并执行，使用代次标记使过期启动失效。新会话覆盖 Map 前必须 dispose；旧会话启动完成后若已过期，立即 dispose，不能遗留 watcher。连续配置更新只保留最后一次完整刷新。

## 扫描性能与配置

文件遍历改为按需递归迭代，不构造完整子目录数组，也不使用参数展开。匹配时逐文件读取，减少大型项目内存占用。

新增 `envSync.syncIgnoreDirectories`，默认包含现有依赖和构建目录名称，用于本地与远端 env 扫描剪枝；嵌套 Git 项目根目录仍始终排除。`gitProjectIgnoreDirectories` 继续只控制项目发现，文档明确两者区别。

保留 130,000 文件不崩溃测试，并增加忽略目录不读取内容的测试。

## 凭据与错误安全

所有用户可见仓库 URL 在日志、通知和 GitCommandError 字段中统一脱敏：移除 HTTP(S)/SSH URL 的 userinfo，并对常见 token 查询参数使用占位符。项目 slug 和分支名不包含凭据。

错误分类保留现有认证、网络、push 拒绝、冲突和 Git 不可用提示，同时增加锁等待、状态损坏和冲突未解决的诊断信息。不得通过脱敏影响实际 Git 命令使用的原始 URL。

## 测试与验收

### 三方同步

- 设备 A 上传新文件，设备 B 保存其他文件后，新文件被拉取且远端保留。
- 已同步文件的本地删除会删除远端；远端新增但未同步到本地的文件不会被删除。
- 远端删除会删除本地；本地删除与远端修改同时发生时提示冲突。
- 冲突选择跳过后，保存其他文件不会覆盖被跳过路径。
- 无基线升级场景不会删除任何仅远端存在的数据。
- 基线写入失败或 push 失败不会被误认为同步成功。

### Git 与恢复

- 项目外 staged 和 unstaged 文件在提交后保持原状，不进入提交。
- commit 成功、push 首次失败，下一次无文件差异同步会推送已有提交。
- 继承数据写入后中断，下一次同步仍会提交。
- 切换配置仓库分支保留本地未推送提交。
- 多分支 FETCH_HEAD、本地提交 rebase 和 autostash 场景通过。
- 两个 manager/进程同时同步同一 clone 时不交叉提交，后者看到前者结果。

### 身份与路径

- GitLab 多级 group、大小写项目和大小写分支使用不同目录。
- 恶意 origin、路径穿越和分支特殊字符不能写出配置仓库。
- 现有分支目录和旧共享目录均可迁移，旧文件保持不变。

### 扩展生命周期

- pull 后立即进行不同内容的用户编辑不会被抑制。
- worktree 切换分支后使用新分支目录。
- 连续配置更新不会遗留 watcher 或重复会话。
- detached HEAD 不执行同步。

### 文档与完整验证

更新中英文 README、配置说明、存储兼容说明和 CHANGELOG。最终运行完整 `npm test`、构建和 VSIX 打包检查；只有全部通过才提交或发布。

## 实施约定

- 不引入新的运行时依赖；锁、哈希、原子状态写入和文件遍历使用 Node.js 内置能力。
- 保持现有设置和命令兼容，新增设置提供默认值。
- 每个缺陷先添加能够复现的失败测试，再做最小实现；复杂同步逻辑优先使用真实文件和真实 Git 集成测试。
- 本设计中的哈希目录、锁租约参数、状态 JSON 字段名和内部结果命名由实现者按现有代码风格确定，但必须满足上述兼容与安全约束。
